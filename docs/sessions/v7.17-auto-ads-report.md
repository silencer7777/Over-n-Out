# V7.17 — Auto-ADS on fire (owner rule change)

Brett's words (Nov 4, ~17:03 PT): "when I fire I want to
automatically aim down the sight." This SUPERSEDES his old
standing rule (ADS = hold right-click only). Manual
hold-right-click ADS still works exactly as before when not
firing; the touch ADS toggle still works too.

## What shipped

- **One aim rule, one place**: `resolveAim()` in
  js/lookfeel.js (pure, DOM-free) decides the frame's aim
  state from three channels — manual (hold right-click),
  touch (ADS toggle), firing (trigger held) — with firing
  blocked while driving, downed, or outside a live match.
  main.js composites it once per frame (`effInput`) and every
  consumer reads the same state: the walker step (solo +
  online) and the online input sample, so the net sim's
  spread sees exactly what the player sees.
- **Feel**: pressing/holding fire raises the weapon into its
  sight picture through the existing ADS machinery — the same
  ~150 ms aimBlend ease, the same FOV zoom per optic, the
  same sight kinds (iron/red dot/holo/mid/sniper overlays
  included). Releasing the trigger eases back to hip unless a
  manual channel is still held. Semi-autos: ADS holds while
  the trigger is held, not just on the shot frame.
- **Interactions, kept sane by inheriting the existing ADS
  rules rather than inventing new ones**: firing from a
  sprint engages ADS and the sprint yields to the ADS move
  speed (sprint was already forbidden while aiming); slide
  entry still requires not-aiming; scope sway/recoil/ADS look
  sensitivity (the ×1.5 precision rate) all ride the same
  `player.aiming` state they always did.
- **Text**: menu hint chip now teaches "FIRE TO AIM DOWN
  SIGHTS — RIGHT-CLICK HOLDS AIM" (touch variant: "TAP ADS
  TO HOLD AIM"); the controls list reads "CLICK — Fire —
  firing auto-aims down the sight…" and right-click is
  described as aiming without firing. The discovery hint
  still retires on first aim — which now includes the first
  trigger pull.

## Balance honesty

No damage, fire-rate, reload, or spread NUMBER changed
(smoke's AR pin is exact). But engaging ADS engages the real
ADS state, which includes the aimed spread multiplier
(`spreadAds`) and the no-move-penalty rule that manual aim
has always carried — so held fire is now as accurate as
held aim, because it IS held aim. That is the feature Brett
asked for, stated plainly rather than hidden.

## Proof

mobile-check **T17** pins the resolveAim truth table against
the shipped function (fire→aim, blocked→no-aim, manual/touch
channels independent, press/release drives ADS in and out)
plus the main.js wiring and the new hint text. Full gate
suite 6/6 green. Perf Δ0.

## For Brett's re-test

Hold fire with any gun: the sight picture comes up on its
own from the first shots and stays up while you shoot; let
go and it drops back to hip. Right-click without firing
still aims like it always did. On the phone, the FIRE button
does the same; the ADS button still latches aim on its own.
