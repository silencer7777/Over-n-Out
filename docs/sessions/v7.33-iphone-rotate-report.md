Owner bug report (Nov 6, 11:18 PT): "It still doesn't rotate on
my [phone] automatically — it does on the tablet but not my
phone. Fix that." Shipped as its own gated slice, ahead of the
character-rebuild slices (Option 3 project), per the parent
agent's instruction. Owner of the fix: **Analog** (Input &
Accessibility), under Trigger; one pen: Coordinator.

## Root cause — stated plainly (two layers stacked into one symptom)

**Layer 1 — game-side (the fixable bug).** The automatic
landscape request built in U8-02 (`goLandscape()` in js/main.js:
element fullscreen, then `screen.orientation.lock('landscape')`)
was wired ONLY to two optional entry points — the menu
LANDSCAPE button and the in-game LANDSCAPE pill. The DEPLOY
button, the one tap every player makes, never asked. So on any
platform, "automatic" rotation silently depended on the player
finding and tapping a side button first.

**Layer 2 — platform (no web game can override this part).**
iPhone Safari does not expose either API `goLandscape()` uses:

- `Element.requestFullscreen` — absent on iPhone Safari
  (present on iPad Safari, desktop Safari, Android Chrome).
- `screen.orientation.lock` — absent on all iOS Safari.

On the tablet, the fullscreen request is honored, so the same
tap visibly presents the game full-screen/landscape — "it
rotates automatically." On the iPhone the identical call is a
harmless, silent no-op (the U8-02 code swallows it by design),
so nothing happened and nothing told the player why. The only
rotation path on an iPhone is the physical turn — and iOS's
own **Rotation Lock** (Control Center) can veto even that. No
website, this one included, can override Rotation Lock or
force-rotate an iPhone. What the game CAN do — and now does —
is ask at the right moment and say the true thing on screen.

## The fix (4 files)

1. **js/main.js — DEPLOY asks.** The touch branch of the play
   handler now calls `goLandscape()` synchronously inside the
   tap, before `touchStartOrResume()` — the fullscreen API only
   honors requests made inside a user gesture, and DEPLOY is
   the gesture every player makes. Platforms that support
   fullscreen/lock now auto-rotate on the main path; the
   LANDSCAPE button/pill remain as alternates.
2. **js/main.js — capability truth at boot.** `AUTO_ROTATE_OK`
   feature-detects element fullscreen (incl. the webkit
   prefix) or `screen.orientation.lock`. A touch device with
   neither gets `body.rotate-manual`.
3. **index.html + css/style.css — the prompt tells the truth.**
   The rotate prompt gains a `.rp-lockhint` line — "STILL NOT
   TURNING? ROTATION LOCK MAY BE ON — SWIPE DOWN FROM THE
   TOP-RIGHT CORNER AND TAP THE LOCK ICON" — rendered ONLY
   under `body.rotate-manual` (iPhone-class platforms), amber,
   width-capped so it wraps inside the pill on a phone. The
   prompt's trigger/clear behavior is unchanged and was already
   correct: pure CSS `(orientation: portrait)` — it appears in
   portrait and vanishes the moment the device turns.
4. **js/main.js — longer refit tail.** The orientationchange
   refit series gains a 1000 ms pass (was 600 ms max): on
   iPhone the landscape browser chrome can still be animating
   at 600 ms, and a fit taken mid-animation can stick, because
   iOS does not guarantee a further resize event. Every refit
   is the same idempotent fit; the extra pass costs nothing.

Preserved untouched: TouchCore, the V7.10 capture routing,
look/stick behavior, the landscape-phone layout query
(max-height 520 px — an iPhone landscape viewport, ~393–430 px
tall, lands inside it, so the compact HUD/button grid applies),
gait/recoil/ADS/minimap/score rules, server posture.

## The check that now guards it (tools/mobile-check.mjs, T18)

- T18a–d: wiring pins — DEPLOY calls `goLandscape()`;
  `AUTO_ROTATE_OK` + `rotate-manual` boot detection; the
  lock-hint markup + its CSS gate; the 1000 ms refit.
- T18e–g: an iPhone-class viewport (393×852 portrait ↔ 852×393
  landscape) flipped through the REAL TouchControls binding —
  the stick viewport follows the turn on both the
  orientationchange and resize re-feeds, so the left-45% stick
  claim zone can never keep portrait geometry in a landscape
  match. (The re-feed itself dates to U9; it was unguarded at
  phone-class sizes until now.)
