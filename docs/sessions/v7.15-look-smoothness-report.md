## What was causing inconsistency (audit, code terms)

The pipeline was audited end to end — mouse (pointer-lock
mousemove → player.look), touch (TouchCore converts finger
px to mouse px at 2.4x, then the SAME player.look — totals
already matched), player smoothing, leans, sway:

1. **The U7-03 error-adaptive rate surged.** The approach
   rate multiplied by up to x2.6 based on the angular error
   sampled THAT frame. The same hand movement got a
   different camera response depending on maneuver and
   frame timing: slow pans trailed at the base rate, then
   the camera accelerated its catch-up as error grew — a
   swell, not a glide. At the adaptive peak the single-step
   integration at 30 Hz also lands measurably off the
   120 Hz path, so refresh rate changed the feel.
2. **The 50 ms frame clamp stalled the camera on hitches.**
   Sim dt clamps at 0.05 s; look targets keep accumulating
   from real input during a stall, so the camera froze,
   then whipped to catch up.
3. **Cosmetic eases used a linear approximation**
   (`min(1, dt*N)`) whose effective time constant drifts
   with frame rate — look lean, strafe lean, run lean,
   view-model sway, ADS blend, FOV ease.

Already sound (verified, untouched): target accumulation
(same drag = same total turn on mouse and touch),
velocity-based sway magnitudes, recoil decay (already
exponential in dt).

## What changed

- **js/lookfeel.js (new, DOM-free):** the look integrator.
  `stepLookAngles` integrates the exponential approach in
  **substeps of at most 1/240 s**, so the discrete path is
  the same curve at any frame rate. The adaptive term is
  **capped at +50%** (was +160%): flicks still catch up
  faster than fine corrections (the U7-03 intent), but the
  gain can no longer surge. Base rate stays the shipped 30
  (~35 ms settle); **ADS still multiplies the rate x1.5**
  — aim-damped precision is coherent, and T16e proves ADS
  settles faster than hip from the same error.
  `easeK(rate, dt) = 1 - exp(-rate*dt)` is the exact
  frame-rate-independent ease.
- **js/player.js:** update() delegates the look approach to
  stepLookAngles (new optional dtLook parameter); the six
  camera-feel relaxations (look lean, strafe lean, run
  lean, sway, ADS blend, FOV) now use easeK. Movement /
  stance / physics eases deliberately untouched — this
  slice is look feel only.
- **js/main.js:** the tick now keeps the raw frame time;
  the sim keeps its 50 ms stability clamp while
  **player.update receives dtLook clamped at 100 ms**, so
  a render hitch no longer stalls-then-whips the camera.
- **Sensitivity meaning unchanged:** look() targets,
  the 0.0021 factor, the touch 2.4x conversion — all
  byte-identical. Only the approach curve changed.

## Verification (tools/mobile-check.mjs T16)

Simulates a 2.0 rad/s pan for 0.75 s (a 1.5 rad drag) plus
settle, stepping the REAL stepLookAngles at 120/60/30/20 Hz
and a jittered ~60 Hz pattern:

- **Settled total turn: 1.5000 rad at EVERY rate** — same
  drag, same turn, exactly.
- Core rates (60/120/jitter) agree mid-pan within 11.7 mrad.
- Low rates stay inside the input-quantization bound (a
  frame of hand motion at 20 Hz is 0.1 rad of input lump —
  no smoothing law can respond to input not yet sampled;
  the check bounds exactly that term).
- Pan lag 60 vs 120 Hz within 20%; ADS faster than hip;
  adaptive cap and base rate pinned.
