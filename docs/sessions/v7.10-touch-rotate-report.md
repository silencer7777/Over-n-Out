## Root cause — stated plainly

Every stage of the look chain that the repo's harnesses exercise
was CORRECT, and was re-proven this session:

- **TouchCore** (js/touchcontrols.js): a right-side drag claims
  the look slot and emits scaled deltas — mobile-check T3.
- **The DOM binding**: reproduced this session with a fake-DOM
  harness driving the REAL TouchControls with realistic
  TouchEvent-shaped objects — layer drags, two-finger
  stick+look, and button claiming all behaved exactly right.
- **main.js wiring**: `player` is constructed (line 76) before
  TouchControls (line ~1770); `hooks.look` calls
  `player.look(dx, dy)`; the `input` object is a const, never
  reassigned; `setActive` runs every frame in `tick()`.
- **player.look / update()**: targets + exponential easing are
  sound; the page stack holds no overlay that can eat touches
  during play (#menu is `display:none !important` via .hidden,
  #hud is pointer-events:none, scope/flash/rotate-prompt are
  pointer-events:none).

The one link NO harness exercised: **event delivery on the real
device**. The binding listened ONLY on #touch-layer, so a look
drag reached the core solely when the phone's browser chose to
deliver that gesture to that one element. On Brett's phone it
doesn't — the drag dies in delivery before any game code runs,
which is why the failure survived two "verified" releases
(cf. the U8/U9 "rotation" incident, same signature: correct
served bytes, dead on the device). The harness gap, not any
single line, is the defect.

## The fix (js/touchcontrols.js, `_bind()` only)

Gesture routing moved to **document-level CAPTURE listeners**:

- Capture sees every touch on the page first, whatever element
  it lands on (canvas, HUD, an overlay, the layer itself), so
  nothing in the page stack can silently swallow a look/stick
  drag again.
- Button semantics unchanged: any touch starting inside a
  `.tc-btn` / `.tc-slot` is skipped by routing (for move/end,
  the event target is the start element, so a FIRE-origin
  finger is skipped for its whole life, exactly as before) and
  the buttons' own handlers are untouched.
- While the layer is inactive (menus), routing is fully inert:
  no feeding, no preventDefault — menu taps/scrolls stay native.
- The old layer listeners were removed (single routing path —
  no double-claim of a touch id as both stick and look).

No changes to the core state machine, look scale, sensitivity,
smoothing, ADS, joystick axes, or any never-regress rule.

## The check that now guards it (tools/mobile-check.mjs, T14)

T14 constructs the REAL TouchControls over a minimal fake DOM
and delivers events the way a browser does — targeted at page
elements:

- T14a layer-target drag → look (sanity).
- **T14b REGRESSION: the same drag targeted at an unrelated
  full-screen element (canvas/overlay stand-in) must still
  reach look.** On the pre-fix binding this fails outright
  (zero document listeners existed).
- T14c button-origin touch claims no look slot; FIRE handler
  still fires; the drag never becomes look mid-gesture.
- T14d two-finger stick+look through the binding.
- T14e inactive layer feeds nothing and never preventDefaults.

Proven both directions this session: with the fix stashed,
T14 reports 6 clean assertion failures; with the fix, all
green (167 checks in mobile-check overall).
